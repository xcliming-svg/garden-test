# Garden Survivors — 플레이 경험·밸런스 목표 정의서 (초안 v0.1)

- 작성일: 2026-11-22
- 문서 성격: **목표 수립·자료 조사 계획**. 새로운 밸런스 수치를 확정하거나 게임 코드를 변경하는 문서가 아니다.
- 기준 게임: [All Aboard! 기차 방어 특급 (Steam 3359200)](https://store.steampowered.com/app/3359200/All_Aboard/)
- 비교 대상: Garden Survivors의 `devel` 기본 생존 모드
- 전제: **난이도 1종, 자동 전투 중심, 무한 웨이브, 꽃 수확·장비 구매·강화**. 비교 게임의 여러 난이도와 영구 해금 체계를 그대로 옮기지 않는다.
- 상태 표시: **확정** = 사용자 확정 또는 코드 확인 / **외부 근거** = 자료로 확인된 사실 / **후보** = 제안, 미승인 / **미측정** = 영상·플레이 로그가 없어 알 수 없음.

## 1. 이 문서의 목적과 결정 순서

**수많은 이동 속도·HP·공격력·드롭율을 먼저 임의 결정하지 않는다.** 먼저 플레이어에게 어떤 시간대에 어떤 경험을 제공할 것인지를 정하고, 이를 측정 가능한 목표(KPI)로 번역한 뒤 게임 변수를 조정한다.

1. **경험 계약**: 한 판의 길이, 방치 가능 정도, 주요 보상·도전 간격, 무한 웨이브의 의미를 정의.
2. **근거 수집**: All Aboard! 개발자 설명·패치 기록·리뷰·편집되지 않은 플레이 영상에서 실제 시간별 수치를 수집.
3. **목표 수치 승인**: 관찰값과 제안값을 분리해 Garden Survivors의 목표 범위와 우선순위를 결정.
4. **인과 모델 수립**: 적 출현·HP·속도·무기 DPS·물 수급·꽃 생산·가격의 상호 영향을 계산.
5. **자동 시뮬레이션 → 실제 플레이**: 여러 난수 시드와 플레이 정책, 브라우저 테스트, 사람의 장시간 플레이를 거쳐 조정.
6. **회귀 기준 고정**: 승인된 목표를 자동 검사로 기록. 새로운 무기나 스탯이 들어오면 같은 지표를 재검증.

**금지할 해석**: Steam의 누적 플레이 시간 = 한 판 길이, 한 명의 장시간 리뷰 = 평균 사용자, 편집 영상 길이 = 게임 내 시간, 근사 경제 시뮬레이션 = 실제 전투 결과.

### 외부 데이터의 범위

- 이 문서만으로 All Aboard!의 **중앙 생존 시간, 10분·1시간 기준 분당 처치 수, 적 동시 수, 구매 가격과 구매 간격**을 알 수 없다.
- 참고 게임은 버전·플랫폼·난이도·영구 해금 여부에 따라 달라진다. Garden Survivors는 **난이도 1개**로 가정하므로 직접 복사하지 않고 **경험 구조만 비교**한다.
- 다른 게임의 실제 게임 내 시간과 영상 재생 시간은 반드시 구분한다. 배속·일시정지·편집이 있다면 별도로 기록한다.

## 3. Garden Survivors의 현재 확정 규칙 및 코드 기준선

> 아래는 **현행 코드·확정 규칙**이고, 목표로서 좋다는 평가는 아직 아니다. 최신 값은 항상 코드에서 재확인한다.

| 영역 | 현재 확인된 값/규칙 | 원천 |
|---|---|---|
| 기본 구조 | 한 가지 난이도를 전제로 한 무한 생존. 공통 정원 HP가 0이면 패배 | `src/run-rules.js`, `src/garden-economy.js` |
| 꽃밭 | 해바라기·장미·수국·라벤더 4종, 전체 동시 확장. 화단당 **1→4→9→16→25송이** | `src/garden-economy.js` |
| 물주기 | 물통 **100**, 드롭 1개당 **20**, MAX에서만 1회 사용, 화단당 **1→5회**, 최종 회차에 전체 개화·수확 | `src/garden-economy.js` |
| 꽃밭 확장 비용 | 각 꽃 종류별 **3 / 18 / 50 / 140송이**. 총 4회 확장 | `src/garden-economy.js` |
| 장비 | 돌멩이 기본, 공격 무기 10종과 패시브 2종. 구매한 무기는 모두 자동 공격 | `src/garden-economy.js`, `src/hero-weapon-preview.js` |
| 드롭 | 물 98.5%, 하트 1.5%, 장비 드롭 없음(현행 생존 규칙) | `src/run-rules.js` |
| 적 등장 | 생존 모드 등장 간격 **2초에서 최소 0.85초**, 목표 동시 생존 수 **8→최대 42** | `src/run-rules.js` |
| 적 종류 | 12종, 0~23분에 순차 출현 가능 | `src/run-rules.js` |
| 적 HP | 시작 후 10분부터 서서히 증가, 이후 최대 2.5배 계수 | `src/enemy-preview.js` |
| 이동 | 정원 요정 40 px/s 시작, 신발 강화 시 현재 최대 66(설정 상한 80); 적 기본 20~48, 종별 1.5배 최대 값은 코드상 비교 기준 | `src/fairy-patrol.js`, `src/enemy-motion.js` |
| 생존력 | 정원 HP 1200, 정원 피해 초당 상한 0.20에서 시간당 +0.14, 최대 0.62, 회복·하트 존재 | `src/garden-economy.js` |

**생산 구조상 계산 가능한 하한**(드롭 손실·미획득·대기시간 없는 이론값): 물통 MAX 한 번에 물방울 **5개**가 필요. 한 화단을 1/2/3/4/5회 물주어 수확하려면 물방울 각각 **5/10/15/20/25개**, 최종 25송이 화단 4개를 모두 한 차례 수확하려면 **100개**가 필요하다. 실제 필요한 처치 수는 획득률·하트 확률·드롭 손실 때문에 더 많을 수 있다.

**처치 연출 목표의 기술적 제한:** 현재 최단 등장 간격 0.85초, 한 등장 기회에 일반 적 1마리를 생성하는 생존 모드이므로, 충분히 처치해도 정상적인 지속 출현만으로는 **분당 약 70.6마리**가 새로운 적으로 공급되는 수준이다(60/0.85). 따라서 '1시간 시점 분당 100~300킬'을 목표로 삼으려면 생성 규칙을 바꿔야 한다. 또한 **누적 수백 킬, 분당 수백 킬, 한 화면 동시 수백 마리, 한 장면의 처치 이펙트 수백 개는 전혀 다른 지표**이므로 별도로 정의한다.

## 4. 플레이 경험 목표 — 승인 전 후보

### 4.1 고정할 방향(수치는 별도 승인)

| 코드 | 목표의 종류 | 방향 | 상태 |
|---|---|---|---|
| G01 | 난이도 | 기본 난이도 하나로 설계하고, 별도 난이도 선택으로 문제를 회피하지 않음 | 프로젝트 전제 |
| G02 | 종료 | 10분이나 60분에 자동 종료시키지 않는 **무한 웨이브** | 프로젝트 전제 |
| G03 | 대형 이정표 | 60분 전후에 체감 가능한 강한 도전/보상 변화가 있는 구조 검토 | **후보** (보스 구현 확정 아님) |
| G04 | 장기 플레이 | 관심을 분산해도 2~3시간 참여할 가치가 있도록 수확·업그레이드·전투 변화를 제공 | **경험 후보** |
| G05 | 경제 | 꽃 수확과 구매가 반복되되 단일 무기·단일 재화 전략만 강요하지 않음 | **품질 후보** |
| G06 | 편의 | 시간이 지날수록 클릭/물주기/구매 조작이 무한히 늘지 않도록 피로도 관리 | **품질 후보** |
| G07 | 성능 | 1~3시간 뒤에도 투사체·적·시각 효과로 인한 프레임 저하를 관리 | **검증 필요** |

### 4.2 시간대별 경험과 측정 항목

**다음 표는 '정량 목표를 정할 자리'이지 비교 게임에서 측정된 결과가 아니다.**

| 게임 시간 | 전달하려는 경험(후보) | 꼭 기록할 지표 | 수치 목표 상태 |
|---|---|---|---|
| 0~5분 | 기본 전투·물 MAX·첫 전체 개화를 즉시 이해 | 첫 물통 MAX, 첫 수확, 첫 적 처치 시간 | **미확정** |
| 5~10분 | 첫 선택의 보상, 구매 또는 확장으로 명확한 변화 | 첫 장비·확장 구매 시간, 수확 횟수, 처치/분 | **미확정** |
| 10~30분 | 적 종류와 무기 조합이 늘어나고 효율 차이가 보임 | 장비 해금 수, 무기별 실제 피해, 회수 물방울/분, 화단 단계 | **미확정** |
| 30~60분 | 화면과 전투가 눈에 띄게 풍성해지고 대형 이정표 준비 | 동시 적 P50/P95, 킬/분, 발사체 수, HP 압박 | **미확정** |
| 60분 전후 | 첫 번째 큰 도전 또는 보상 전환점(기준 게임의 Super Boss는 **참고**만) | 주요 이벤트 도달률, 이벤트 전후 성능·생존·보상 | **미구현 / 미확정** |
| 60~120분 | 확장·강화를 통해 강력한 화면을 만들되 방치만으로 무의미해지지 않음 | 무기별 기여도, 수확 간격, 구매 간격, 실패 원인, 처치 연출/초 | **미확정** |
| 120~180분 | 성장 정체·과도한 조작·성능 저하 없이 장기 생존 | 생존 곡선, 미사용 자원, 조작량, 프레임 시간 P95, 이탈 시점 | **미확정** |
| 180분 이후 | 종료가 아닌 무한 생존: 난이도 증가의 상한·반복 이벤트·자발적 종료 고려 | 정체 구간, 10분당 의미 있는 선택, 이벤트 반복, 성능·저장 | **미확정** |

### 4.3 정량 목표의 **첫 협의 후보** — 측정 전 확정 금지

아래는 내부 토론을 시작하기 위한 **실험용 조건**이다. All Aboard!의 플레이 로그에서 추출한 수치가 아니다.

| 항목 | 제안하는 검토 기준 | 근거 수준 | 승인 조건 |
|---|---|---|---|
| 첫 유의미한 구매/수확 선택 | **10분 이내 경험 제공**을 우선 실험 | 설계 제안 | 신규 사용자 5~10회 직접 플레이 |
| 큰 난이도·보상 이벤트 | **60분 전후** 주요 이정표의 필요성 검토 | B03의 시간 구조를 비교하되 동일 적용 미결정 | 이벤트 유형·보상·준비 시간 정의 |
| 1회 플레이 길이 | **1시간을 주요 평가 지점**, **2~3시간을 장기 평가 지점**으로 설정 | B02~B04, 사용자 목표 | 초보·보통·숙련 3정책 테스트 |
| 한 시간 시점 '화려한 전투' | 우선 **분당 처치량 / 동시 적 / 시각 이펙트 빈도** 가운데 무엇을 의미하는지 명시 | 사용자 예시, 현재 출현 상한과 별도 | 영상에서 실제 수치 추출 및 성능 측정 |
| 장기 조작량 | 수확·상점 재방문 등 **분당 입력 수를 실측**하고 피로 허용선을 결정 | B07의 문제 제기 | 실측 + 직접 플레이 주관 평가 |
| 무한 웨이브 | 수명·난이도 성장·화면 점유율 중 어느 제한 때문에 한계가 오는지 분리 | 설계 원칙 | 게임 버전/플레이 정책별 생존곡선 |

'모든 사람이 2~3시간 살아야 한다', '1시간에 수백 마리를 반드시 죽여야 한다' 등은 현재 결정된 사실이 아니며, 위 계량 결과를 바탕으로 승인을 받아야 한다.

## 5. 밸런스 변수의 전체 **범주** (세부 파라미터 명세는 후속 문서)

| 범주 | 실제로 변동하는 요소 예시 | 주요 출력 지표 | 우선 조정 여부 |
|---|---|---|---|
| 플레이 시간/진행 | 이벤트 시간표, 적 종 해금 시간, 확장 단계 | 이벤트 도달률·세션 길이 | **먼저 목표 승인** |

| 무기 | 피해량, 실효 발사 주기, 탄속, 관통, 사거리, 투사체 수명, 적중률, 타깃 규칙 | 실효 DPS, 킬 기여, 과잉 피해 | 조정 |
| 상태 효과 | 둔화 지속/효율, 넉백 거리, 광역 반경, 중첩 규칙, 향후 치명타/방어 관통 | 적의 유효 접근 속도 | 조정·일부 미구현 |
| 정원 생존 | 전체 HP, 방어·회복, 피해 상한, 하트 회복량/빈도, 사망 처리 | 누적 피해, 생존율, 치명 위험 시간 | 조정 |

## 6. 자료 수집 프로토콜

### 6.1 원자료 우선순위

1. **개발자 공식 기록**: 보스 시간표, 난이도 공식/패치, 해금 제도. 버전별 변화를 명시. 높은 신뢰도지만 플레이어 실제 평균은 별도.
2. **장시간 원본 플레이 영상**: 편집/배속/일시정지 여부를 확인한 뒤 게임 HUD의 시간대를 기준으로 관찰. 직접 게임을 플레이하지 않은 경우 타임스탬프별 표시 수치만 기록.
3. **리뷰/토론**: 지루함·과도한 클릭·지배적 전략·갑작스러운 사망을 주제별 분류. 선택 편향이 있으므로 생존 시간 분포를 대표한다고 해석하지 않음.
4. **자체 게임 텔레메트리**: 동일 코드·시드로 반복한 자동 플레이와 실제 사용자 플레이를 분리해서 기록.

### 6.2 영상 추출 양식 (한 영상당 시트 하나)

| 필드 | 기록 내용 |
|---|---|
| 출처 | URL·채널·게시일·게임 버전·플랫폼·난이도 |
| 재생 방식 | 원본/편집/배속/라이브, 실제 재생 시간과 게임 시간 관계 |
| 시간 스냅샷 | **게임 시간** 0·5·10·15·30·45·60·90·120·180분. 영상에 없으면 결측(NA) |
| 적 | 출현 수/분, 처치 수/분, 동시 수, 특수 적/보스, HP/공격 변화가 읽히면 기록 |
| 전투 | 무기 수와 레벨, 분당 유효 공격/적중, 폭발/죽음 연출, 화면 혼잡도 |
| 경제 | 구매·강화 시점/비용, 수입·자원 재고, 거래 빈도 |
| 장시간 결과 | 종료 시간·사망/자발 종료·사유, 주관적 피로·정체 구간 |
| 근거 | 해당 화면의 영상 타임스탬프, 화면에 수치가 보였는지(정확/추정/불명) |

**현재 발견한 영상 후보:** [S08], [S09]. 둘 다 영상의 상세 수치를 아직 추출하지 않았으므로 표에 숫자를 채우지 않는다.

### 6.3 실제 게임 측정용 최소 이벤트 로그

- `run_start`, `run_end`: 빌드 SHA·시드·실제 경과 시간·게임 경과 시간·종료 원인.
- `enemy_spawn`, `enemy_kill`, `enemy_hit_garden`: 적 종류/레벨/HP, 출현→처치 시간, 출현 위치, 정원 피해.
- `weapon_fire`, `weapon_hit`, `weapon_kill_credit`: 무기 종류/강화, 발사·명중·피해, 중복 피해·과잉 피해.
- `water_drop`, `water_collect`, `water_max`, `water_use`, `flower_harvest`: 생성·회수·손실, MAX 대기시간, 화단별 수확 주기.
- `shop_open`, `item_buy`, `item_upgrade`, `garden_expand`: 상품·화폐 지출·보유 꽃·강화 효과.
- 1분 요약: 적 출현·처치·동시 적 P50/P95, 정원 HP, 물 수급, 꽃 생산량, 구매량, 클릭·키 입력 수, 프레임 시간 P50/P95.

**플레이어 프라이버시:** 수집이 필요한 것은 게임 내 익명 지표뿐이다. 실제 플레이 텔레메트리를 연결할 때는 동의·보관 정책을 별도로 결정한다.

## 7. 목표 채택 판정 방식

지표마다 **측정 단위**, **측정 구간**, **대상 정책**, **통계량**, **허용 범위**, **출처/추정 수준**을 하나의 레코드로 관리한다.

예시(목표값은 아직 없음):

```yaml
metric_id: first_new_weapon_time
unit: game_minutes
population: new_players
run_type: single_difficulty_endless
aggregation: median_and_p90
baseline_value: null        # 현행 게임 실측 전
benchmark_value: null       # All Aboard! 측정 전
target_min: null            # 승인 전
target_max: null
source_ids: []
status: pending_evidence
```

**채택 순서:** 외부 비교 관찰 ≥ 3개 출처(가능한 경우) → 경험 목표 범위 초안 → 프로젝트 승인 → 같은 시드로 기준선·후보 비교 → 실제 1시간·3시간 플레이 검토 → 회귀 목표 고정.

표본 수 3개는 조사 시작을 위한 최소 자료 출발점이지 통계적 충분 조건이 아니다. 영상/플레이 표본이 적으면 **가설로 유지**하고 확정하지 않는다.

### 아직 결정해야 할 핵심 질문

1. 장기 생존 경험이 **한 판의 60분 완주형**인지, **60분 대형 이정표 + 2~3시간 무한 도전형**인지.
2. 2~3시간의 기준이 **처음 플레이한 사람 / 일반적인 플레이어 / 장비 이해도가 높은 플레이어** 중 누구인지.
3. '1시간 후 수백 마리'가 **누적 처치 / 분당 처치 / 동시 적 / 한 장면의 시각 효과** 중 어느 지표인지.
4. 60분 이정표에 **보스**가 필요한지, 아니면 신규 웨이브·대형 상점 해금·화단 완성 같은 변화로 충분한지.
5. 끝없이 강해지는 게임을 원하는지, 장기 플레이를 위해 적 성장 속도에 상한 또는 완만한 구간을 둘지.
6. 자동 방치의 목표가 **적극적으로 물주기를 반복하는 가벼운 게임**인지, **일정 시점부터 거의 손을 떼도 되는 방치형**인지.

## 8. 즉시 진행할 조사 순서와 완료 조건

| 순서 | 작업 | 산출물 / 통과 기준 |
|---|---|---|
| 1 | All Aboard! 공식 개발 기록 시간표 정리 | 보스·난이도·경제·패치의 구간별 공식 변화 |
| 2 | 원본/장시간 게임플레이 최소 3개 수집 | 영상별 실제 게임 시간과 0·10·30·60·120·180분 관찰표; 확인 불가능한 값은 NA |
| 3 | 주요 리뷰의 장시간 불만·좋았던 점 분류 | 리뷰별 URL·표현·플레이 단계·신뢰도, 사례/통계 구분 |
| 4 | Garden Survivors 같은 조건으로 플레이 로그 생성 | 동일한 시간 스냅샷과 유효 킬/분, 경제/분, 동시 수 지표 |
| 5 | 목표값 후보 및 충돌관계 제시 | 10·30·60·120·180분 목표표, 목표의 근거 및 달성 가능성 |
| 6 | 숫자 승인 후 파라미터 조정 | 새 시뮬레이션·브라우저·사람 플레이 결과와 근거를 함께 기록 |

현재는 **1단계의 일부 근거만 확보**한 상태이며, 시간별 상세 게임플레이 관찰표는 채워지지 않았다. 이 문서는 목표 승인 전까지 설계 초안으로 유지한다.
