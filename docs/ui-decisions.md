## 1. 레이아웃

| 요소 | 확정 |
| --- | --- |
| 전장 논리 좌표 | 640×360, 16:9 |
| 상단 HUD / 전장 / 하단 | 24 / 300 / 36px |
| 정원 | x=235, y=89, 170×170, 16px 면 + 1px 공백, 17px 간격 × 10×10 |
| 도안 | x=8, y=32, 99×115 펼침 / 99×16 접힘, 내부 8px + 1px 공유선 × 10×10 (외곽 포함 91×91), 헤더 16px, 패딩 4px |
| 장착 슬롯 | 하단 중앙, 24×24, 간격 2px, y=330, 초기 일반 4칸 + 확장 1칸, 최대 일반 10칸(설계); 현 시안 9+1 |
| 간격 체계 | 2 / 4 / 8 / 12 / 16px |

상단은 두 줄 36px 안보다 한 줄 24px 안을 선택하여 전장 면적을 확보했다. 하단은 슬롯 크기 때문에 36px 유지. 정원은 화면 전체가 아닌 전장 중앙에 위치한다. 도안 접기/펼치기는 전장이나 정원 위치를 바꾸지 않는다.

## 2. HUD 표시

순서: **시간 → 처치 수 → 보석 → 정원 완성도**. 앞 세 영역은 같은 폭(최소 144px, 실제 글자 폭·예약 자릿수에 따라 8px 단위로 함께 확장). 마지막 완성도는 잔여 폭을 사용한다. 좌우 패딩 각 8px, 레이블/아이콘 뒤 4px 간격, 수치 좌측 인접 배치, 세로 중심 y=12. 숫자만 오른쪽 끝에 고정하지 않는다.

| 항목 | 초기 표시 | 표시 폭 예약 |
| --- | --- | --- |
| 시간 | 00:00:00 | 9999:59:59, 시는 최소 2자리 |
| 처치 수 | 0 | 999,999,999,999 |
| 보석 | 12px 아이콘 예약 자리 + 0 | 처치 수와 동일 |
| 정원 완성도 | 30% | 게이지 내부 높이 8px, 외곽 포함 높이 10px, 최소 폭 64px, 수치 중앙 |

가장 넓은 숫자 글리프와 구분기호의 실제 폭으로 계산한다. 4자리 시 및 12자리 카운터는 게임 상한이 아니다. 초과 값은 실측 폭에 반영하되 최소 게이지 폭이 부족하면 현재 배치 함수가 오류를 낸다. 극단값 표시 정책은 게임 수치 규칙 확정 시 별도 결정한다. `?hud=stress`는 예약 폭 확인용이다. 30%와 999(슬롯 비용) 및 모든 카운터는 정적 시안이며 게임 데이터가 아니다.

## 4. 폰트 및 렌더링 — 최종 sharp

- Fusion Pixel 10px Proportional KO Regular(400) 단일 원본. 한글·영문·숫자 공통. 10px 기본, 20px 강조, 30px 제목. 메뉴는 1280×720 디자인 좌표에서 2배 크기. 하단 능력치·정보창 7px, 확장 비용 7px(필요 시 6px)는 예외.
- 로컬 WOFF2 내장 CSS, OFL 라이선스 및 출처 보존. Phaser 시작 전 폰트 로드, 실패 시 대체 폰트로 실행하지 않는다. 정확한 upstream 버전은 미확인.
- 실제 카메라 배율(최소 1)로 텍스처를 래스터화하고 개별 텍스처에 NEAREST 필터 적용. Text 갱신 시 필터 재적용. 창 크기 변경 시 style.resolution과 frame.source.resolution 동기화. 전역 antialias=true, pixelArt=false, roundPixels=false 유지.
- 1배 텍스처 고정 확대는 사용자 확인에서 흐려져 폐기. linear보다 sharp가 조금 나았고 crisp와 sharp는 차이가 미미했다. 글리프 알파 직접 보정 및 비교용 URL 분기는 제거하여 sharp 단일 방식 확정.
- 16:9 창 맞춤, 비정수 배율 허용. 정수배 화면에서 유리하나 비정수 배율의 픽셀 불균일 및 브라우저/OS 차이는 남을 수 있다.
- 코드: [src/ui.js](../src/ui.js), [src/main.js](../src/main.js), [assets/fonts/README.md](../assets/fonts/README.md).

## 5. 검증과 미확정 범위

최종 렌더링 구현 커밋에서 전체 5개 JS 구문, 9개 씬 생성, 10개 창 크기(320×180~7680×4320), 텍스트·색·크기 변경 시 NEAREST 유지, Canvas 해상도 동기화, 씬 종료 추적 해제, 일반/장시간 HUD 모의 테스트를 통과했다. 색 대비 및 32색 고유값 검사도 통과했다. 사용자가 실제 화면에서 폰트 비교를 수행했으나 자동화된 실제 브라우저 렌더링 검증 및 완성 에셋 검증은 미실행이다.

## 7. 아이템 카드 UI 확정 — feature/item-card-ui

- 하단 36px로 복원, 전장 300px, 정원 y=94. 중앙 24px 일반 9칸과 비활성 확장 1칸(999), 슬롯 간격 4px, 좌우 126px(42px×3열), 바깥 여백 8px, 슬롯과 그룹 사이 48px. 실제 초기 슬롯 설계 유지.
- 능력치 6종: 방어력·최대 체력·행운 / 이동 속도·획득 범위·초당 피해량. 별도 분류 제목이나 꽃 접두어 없이 표시한다. 행운은 필요한 꽃의 등장 확률과 연관되나 실제 계산식 미정.
- 카드·장착 슬롯의 오버/클릭 정보창, 드래그 대상 슬롯 강조, 예상 최종 수치와 증감, 장착/교체 및 취소를 UI 검토 범위로 적용한다. 실제 전투·게임플레이·저장·확장은 미구현이다.
- 검증: JS 구문 및 모의 이벤트, 9+1 배치, 카드/장착 슬롯 선택, 6개 수치, 교체, 확장 슬롯 거부, 취소, 2.5배 좌표 변환, 정보창 경계 108개 조합, 이벤트 해제 통과. 실제 브라우저 시각 검증 미실행.

- 후속 비교에서 레이블·수치·증감 모두 7px로 변경. 각각의 42×36px 영역에서 두 줄을 가로·세로 중앙 정렬하고, 실제 텍스트 상자 사이 3px, 수치 오른쪽 증감 사이 2px 간격을 적용한다. 이 비교 이후 하단 배치를 확정했다. 아이템 정보창도 7px로 맞추되 상단은 10px 유지한다. 정보창은 고정 폭 120px, soil 배경, edge 구분선 및 카드 선택과 동일한 Rectangle 1px 중앙 스트로크 paper(#F1F0E8)로 정리한다. 제목 → 구분선 → 설명 → 효과 수치 순서. 교체 제목은 A안(실측 너비가 맞으면 한 줄, 넘치면 화살표 앞 줄바꿈, 개별 이름이 길면 추가 줄바꿈), 긴 설명은 줄바꿈하여 높이만 조절한다. Garden 32 색상 유지. 장착 슬롯 선택·빈 슬롯 장착 대상·기존 아이템 교체 대상 강조는 모두 골드(#F4B404)로 확정한다. 증가/감소 색상과 확장 슬롯 상태 색은 유지. 실제 글꼴 가독성은 사용자 확인 필요.

### 메뉴 공통 색상 및 테두리 통일

- 사용자 승인: 주요 메뉴 버튼·활성 탭·일시정지·게임 제목의 황록색을 paper(#F1F0E8)로 변경한다. 성장·성공·증가 및 기존 확장 가능 상태는 growth 유지. gold는 아이템 강조, 개발용 안내는 label로 변경한다.
- 기능적 테두리/구분선은 640×360 논리 1px(기존 메뉴 좌표 2px), 호버 시 두께 고정. 일반 버튼 호버 paper, 위험 버튼 red 유지. 주요 행동과 선택 탭의 상태 속성은 분리한다. 일반 팝업/구분선 edge 유지. 기존 전장·하단·정보창 규격 및 메뉴 배치 유지.
