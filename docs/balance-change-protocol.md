# 밸런스 콘텐츠 추가·변경·삭제 프로토콜 (v1.0)

> 적용 대상: 현재 Garden Survivors 단일 난이도 생존 게임. 바꾸는 값·기능마다 시뮬레이션의 유효성과 이전 실험 재현성을 검증한다.
> 참고: [수치 전체 목록](./balance-parameter-inventory.md), [의존관계/경고선](./balance-dependencies-guardrails.md), [목표 KPI](./balance-goals-benchmark.md), [시뮬레이션 실행/인계](./survival-simulation-handoff.md).
> **이 문서는 변경 관리 규칙이며, 새로운 무기 가격·최종 강화 상한·물요정 기능을 승인한 문서가 아니다.**

## 1. 현재 확정 규칙과 임시 한계

- **역할 규칙**: 현재 생존 게임에서 **한 번의 발사로 여러 개의 기본 투사체를 동시에 던질 수 있는 무기는 돌멩이뿐**이다. 다른 9종의 '다중 발사' 업그레이드는 상점에 나타나지 않으며 구매할 수 없다. 무기 자신의 광역 폭발·왕복·연쇄·반복 타격·물줄기/파편의 시각 효과는 **별개 기능**으로 보존한다.
- **설정 원천**: \`src/garden-economy.js\`의 \`upgradeLimits\`와 \`upgradeTypes\`. \`src/scenes.js\`는 여기에서 상점 항목·상한을 구성하고, \`src/hero-weapon-preview.js\`도 생존/꽃 경제에서 돌멩이만 추가 투사체를 발사하도록 독립적으로 제한한다.
- **현재 기술적 범위**: 돌멩이 \`volley\` 강화 0~3회 → 발당 1~4개. **4개 상한은 기존 구현 보존값**이며 사용자가 최종 설계값으로 확정한 수치가 아니다. 무기의 기본 피해·사거리·쿨타임·가격, 물통 MAX·꽃 수확 횟수는 이번 역할 정리로 바꾸지 않는다.
- **현재 무기 강화**: 공격 무기 위력 강화 2회(레벨 1~3), 공격 속도 강화 3회. 추가 발사는 돌멩이에만 3회. 패시브 신발·방패는 위력 강화 3회만.
- **과거 비교 모드와 구분**: \`GardenFairyCombinations\`가 사용하는 기존 물요정·합체 미리보기 경로는 과거 실험 코드다. 현재 생존 꽃 경제의 '돌멩이 전용 다중 발사'와 혼합하지 않으며, 물요정을 다시 정식 투입할 때 게임 규칙에 맞게 별도 통합해야 한다.

## 2. 값의 상태와 변경 단위

| 종류 | 사례 | 수정 승인 |
|---|---|---|
| 게임 구조 고정 | 난이도 1개, 무한 생존, 꽃 4종, 화단 1→4→9→16→25, MAX 물주기 1→5회 | 게임 규칙을 바꾸는 별도 승인 |
| 역할 고정 | 기본 다중 투사체 강화는 돌멩이만 | 역할 변경 시 설명과 전투 테스트 필요 |
| 임시 범위 | 돌멩이 최대 4개, 무기 가격·개별 쿨타임·적 출현값 | 실제 전투 지표 측정 후 승인 |
| 출력 목표 | 10/30/60/120/180분의 생존율·분당 처치·꽃 수확·선택 주기 | 비교 게임/실제 테스트 후 승인 |
| 구현 예정 | 물요정 재투입과 그 기능·효과·수·강화 | 기능 계약과 역할·범위 승인 전 효과를 가정하지 않음 |

수치/역할 변경에는 **가설**, **변경 전 값**, **제안값**, **예상 영향 KPI**, **원본 소스**, **실험 정책/시드**, **전투·경제 결과**, **위험/회귀 결과**, **승인 여부**를 기록한다.

## 3. 신규 무기·유닛·스탯 추가

**무기 추가:** (1) 식별자/역할/상성을 먼저 정의 (2) \`src/garden-economy.js\`의 \`weapons\`·\`inventory\`·\`upgradeLimits\`를 점검 (3) \`src/weapon-balance.js\`에 피해·사거리·쿨타임 규격 추가 (4) \`src/hero-weapon-preview.js\`에서 발사·충돌·이펙트 정의 (5) SVG/전리품/UI 연결 (6) 모델/브라우저 회귀와 시뮬레이션 시나리오 동기화. 신규 무기의 \`volley\` 상한은 별도 승인 전 **0**이다. 식별자만 추가하고 실제 투사체 모델을 빠뜨린다면 사전 점검에서 실패하도록 검사를 보강한다.

**적 추가:** (1) \`src/enemy-preview.js\` 적 목록 (2) \`src/enemy-motion.js\` 속도·사거리·동작·공격 예고 (3) \`src/weapon-balance.js\` HP와 상성 (4) \`src/run-rules.js\` 도입 시간·선택 분포 (5) 모델/브라우저 검증. 미리보기 전용 적과 생존에 실제 등장하는 적을 구분한다.

**스탯/강화 추가:** (1) ID·단위·기본·최솟값·최댓값·단계 수·중첩식 지정 (2) 최소 1가지 강점과 무효 상황 명시 (3) 상점 구매가격·캡·실제 전투 적용을 동일한 정의에서 관리 (4) 파라미터 스키마·시뮬레이터·결과 로그·모델/브라우저 테스트 추가 (5) 같은 시드·정책으로 기존 빌드와 비교. 새로운 스탯이 \`damage\`, \`volley\`, \`speed\` 외 이름이라면 현재 \`upgradeLimits\`·\`state.upgrades\`·\`cost\`·\`bonus\`·상점 UI가 자동 지원한다고 가정하면 안 된다.

**물요정 재투입 예정:** 복귀 자체는 방향이며, 정확한 기능은 미승인이다. 최대 동시 수, 순찰/정지/물 회수/물주기/공격/상점 해금 및 다른 무기와 시너지를 한 번에 정하지 않는다. 물요정이 실제 발사체를 증식시키는 기능이 있다면 돌멩이 전용 역할 규칙과 충돌하므로 별도 의사결정이 필요하다. 물요정 관련 이벤트·효과량·개입 시간·성능 한계를 기록하고, **물요정을 실장하기 전의 장기 시뮬레이션 값은 최종 밸런스 근거로 고정하지 않는다**.

## 4. 변경·삭제에서 데이터 무결성을 유지하는 방법

- **숫자 조정:** 원래 게임 코드를 직접 여러 번 덮어쓰지 말고, 비교용 실험 설정과 유효 범위에서 후보를 탐색한다. \`sourceHash\`·실험 설정·시드·플레이 정책을 저장한다.
- **기능 변경:** 기존 이벤트와 수치의 의미가 바뀌면 출력 스키마 버전을 올린다. 예: \`volley=3\`의 의미를 한 번에 4개 발사에서 3개 보유로 바꾸면 같은 숫자라도 별개 규칙으로 취급.
- **아이템 삭제/대체:** 인벤토리, 상점, 무기 스탯, 발사체, 드롭/해금, 아트, 테스트, 실험 파일 참조를 전부 확인한다. 이전 실험 파일에서 삭제된 ID를 자동으로 다른 ID로 치환하지 않는다. 오래된 결과는 해당 커밋의 기록으로 보존한다.
- **적 삭제/대체:** 적 목록·모션·HP·해금 목록·시뮬레이션 적 분포·예측 조준·테스트에서 고아 참조를 검사한다.
- **강화 제거:** 상점에서만 버튼을 숨기면 부족하다. 가격 함수, 구매 실행, 실제 효과, 모델 기반 시뮬레이션에서도 동일하게 금지해야 한다. 이전 저장 데이터가 생기는 시점에는 버전별 마이그레이션 또는 명시적 거부를 설계한다.
- **가정 변경:** '회수율 100%'처럼 경제 근사 시뮬레이터의 가정을 바꾸면 이전 요약과 직접 비교하지 않고 별도 실험 엔진/시나리오 버전을 기록한다.

## 5. 의존도와 기본 검증 세트

| 변경 | 반드시 함께 보는 지표 | 필수 테스트 |
|---|---|---|
| 무기 피해·쿨타임·사거리·발사 수 | 유효 DPS, 킬/분, 물 획득, 꽃/분, 정원 HP | 무기 모델·생존 모델·브라우저 |
| 적 속도·HP·스폰 | TTK, 동시 적, 정원 도달 시간, 처치·수급·수확 | 적 모션·전투 모델·생존 |
| 물요정 수·속도·행동 | 요정 순찰/수거율/물주기/별도 무기 효과/프레임 시간 | 실제 생존 브라우저+신규 자동 플레이 |
| 물통·물 드롭·수확 | MAX 주기, 화단별 개화 횟수, 구매 시간 | 생산 모델·경제 시뮬레이터 |
| 상점 가격·해금·강화 단계 | 첫 구매/전체 구매 시간, 빌드 지배 여부, 자원 병목 | 생산 모델·경제 정책 비교 |
| 오브젝트 크기·물리·렌더링 | 적중 판정, 경로 간섭, 화면 밀도/P95 프레임 | 브라우저/기하/장시간 검사 |

**실행 순서:** \`node simulation/survival-preflight.mjs\` → \`node tests/garden-economy-model.mjs\` → \`node simulation/garden-economy-balance.mjs simulation/experiments/garden-economy-10x10.json --check\` → 설치된 Playwright 기반 \`node tests/garden-economy-browser.mjs\` → 실제 게임으로 보이는 연출/조작 확인. 기존 \`simulation/cli.mjs\`는 현재 생존 게임 검증용이 아니라는 점에 유의한다.

## 6. 변경을 승인하는 기준

1. 새 항목이 장비/적/물요정 어느 부분에 들어오는지, 무엇을 대체하는지 설계 근거가 있어야 한다.
2. 반드시 지켜야 하는 규칙(HARD)과 사람이 보고 판단할 경고(WARN)를 구분한다.
3. 실제 생산 모델과 상점이 새 캡·효과를 그대로 읽고, 명시적으로 불가능한 강화는 재화를 소비하지 않는다.
4. 현행 경제 근사 결과가 바뀌어도 그것만으로 전투가 좋아졌다고 주장하지 않는다.
5. 버전·시드·에이전트·자산·실험 가정·실행 엔진을 보고서에 남긴다.
6. 변경 전후 테스트에 실패하면 기본 브랜치에 병합하지 않고 수정·재검증한다.
7. 실질적인 대규모 조합 조정은 **물요정 통합 + 실제 전투 headless 검증기의 브라우저 동치성 검사** 후에 시작한다.

**현 단계의 결론:** 돌멩이 다중 발사 능력을 고유 역할로 잠그고, 나머지 무기의 공격력·공속·고유 효과 범위와 최종 업그레이드 수치는 새로운 실제 전투 로그가 갖추어질 때 결정한다.
