# Garden 16 — 게임 공통 색상 가이드

> 현행 devel: 기존 참조 화면의 색감과 원본 에셋의 표현을 우선하는 16색 공통 설계. 이전 청회색 16색은 대체된 시안이다.
> 색상 원본: [src/palette.js](../src/palette.js). 좌표·크기는 [현행 UI 규격](./resolution-960x540.md), 간격은 [UI 간격 가이드](./ui-spacing-guide.md)를 참조한다.

## 1. 설계 기준

사용자가 선호한 기존 화면(공통 규격 정리 이후 `613ba9b`, UI 16색 통합 `2062627`)의 전장·HUD·보라회색 표면·제목·테두리 관계를 보존한다. 참고 이미지의 색상을 무조건 복사하는 대신 명도/채도/색온도 관계를 우선한다. 청회색 전면 변경과 원본 색 관계를 고려하지 않은 스프라이트 변환은 원래 색감을 약화했으므로 대체한다. 참고 UI는 명도·채도·색온도 관계의 자료, 객체 시트는 소재 및 종류별 색 범위의 자료로 함께 사용한다. 두 자료를 고려해 16색을 선정하고 실제 UI와 에셋 표시 색에 적용한다.

## 2. 색상 선정 근거

참고 UI의 배경·HUD·표면·제목·그리드·외곽의 단계는 기존 화면에 가까운 저채도 보라회색 8색으로 확보한다. 객체의 대표 색 범위는 흰색/회색(종이·토끼·돌·금속), 갈색/베이지(화분·손수레·달팽이·참새), 노랑(꽃·빗자루), 분홍/빨강(튤립·자석·위험), 녹색(잎·곤충), 청록(캐릭터·스프링클러), 청색(수국·물·장비), 보라(나방)이다. 흰색/회색 및 저채도 연보라는 UI 중성색과 공유하고, 나머지 자연색은 8개로 확보한다. 기존 UI 색과 기존 객체 색에 가까운 값을 우선 사용하며, 새 색을 고를 때 일반적인 소재 인식과 실제 목표 크기의 실루엣을 함께 고려한다. 16색 제약 때문에 선명한 보라, 별도 짙은 녹색/청색, 주황은 독립색으로 확보하지 못하며 가까운 소재색과 명암을 활용한다.

## 3. 공통 팔레트

## 4. UI 역할 및 명도 체계

- 전장과 메뉴 배경은 ink, 상하 HUD는 hud로 분리한다. 일반 슬롯·카드·도안·정보창·버튼·팝업 본문은 panel, 제목은 header, 선택 및 호버 면은 slate. 비활성 면과 빈 게이지는 hud. 기존 화면의 저채도 보라회색 표면과 명도 차이를 우선한다. 팝업 본문과 일반 표면이 같은 색을 사용하므로 기존 UI의 더 어두운 팝업 면과는 차이가 있다.
- 일반 메뉴 외곽 테두리는 stone, 정원·슬롯·드롭·정보창 기본선은 slate. 메뉴의 주요 행동·포커스는 silver. 꽃·손수레는 기본 면 panel을 유지하며 오버/드래그 및 유효 목적지의 기존 선만 각각 growth/sky로 변경한다. + 표시 없음. HUD 및 도안 외곽 경계는 panel/slate, HUD 내부 구분은 ink. 도안 내부 공유선은 slate.
- 주요 글자·수치·제목은 paper, 보조 설명과 레이블 및 비활성 비용은 silver. 비활성 상태는 낮은 명도의 면·조작 불가·보조 글자와 함께 구분한다. silver는 기존 회색과 가까운 저채도 연보라를 겸하며 전용 보라색을 별도로 늘리지 않는다.
- 증가·성장·배치 가능은 growth, 감소·위험은 red, 주의는 gold, 청색 자원·물은 sky. 상단 보석 자리의 예약 아이콘은 차분한 silver를 사용한다. 강조는 의미가 있는 상태에만 적용하고 장식적인 색을 임의 추가하지 않는다.
- 성공/실패는 주요 제목과 상태색 테두리로 구분한다. 위험 버튼은 일반 면을 유지하고 포커스 경계로 호버를 표시한다. 색만으로 정보를 전달하지 않는다.

## 5. 객체 제작 원칙

1. **소재와 일반적 인식 우선:** 흰 종이·토끼는 paper/silver, 회색 물체는 중성 단계, 나무·화분·달팽이는 자연 갈색·베이지, 꽃·잎·물은 대표색을 선택한다. 원본과 가장 가까운 색상 역할부터 정한다.
2. **실루엣과 명암 보존:** 실제 목표 크기에서 기본색 하나와 필요한 그림자/하이라이트로 시작한다. 색 수 자체를 줄이는 것보다 형태, 소재, 세부 표현이 중요하다. 흰색과 크림색은 별개 역할이다. 어두운 물체에는 필요한 부분만 중성 밝은색을 사용한다.
3. **색의 재사용:** 신규 UI와 에셋은 공통 16색을 제작 기준으로 사용한다. 유사한 역할에 임의의 새 HEX를 선언하지 않는다. 필요한 색이 없으면 기존의 가까운 소재/명도 색을 먼저 시도하고 원본과 목표 크기 비교로 평가한다. 예를 들어 연보라 소재는 silver를 활용할 수 있으나 원본의 선명한 보라와 같지는 않다.
4. **원본과 실제 표시를 분리:** 기존 꽃·달팽이·손수레 샘플의 원본 픽셀 인덱스·RGBA는 그대로 보관한다. 실제 게임 및 비교 페이지에서는 `test-sprites.js`의 소재 역할에 따라 16색으로 표시한다. 기존 데이지의 크림색과 해바라기의 금색, 튤립의 분홍색, 수국의 파란색, 손수레·달팽이의 자연 갈색에 가까운 값을 사용하며 수국에는 밝은 중성 하이라이트를 사용해 꽃잎 형태를 구분한다. 알파·형태·크기는 보존하되 일부 원본 색의 차이는 줄어든다.
5. **색상 변경 관리:** 모든 신규 실제 게임 에셋은 16색을 사용한다. 표현이 부족하다면 실제 크기에서 색·명암·형태를 개선하고 팔레트 수정이 필요한 근거를 기록해 승인받는다. 원본을 덮어쓰거나 임의 색을 추가하지 않는다.

## 6. 대비와 검증

sRGB 명암비(일반 면 #3B3B4E / 제목 면 #44445C): 주요 글자 10.93:1 / 9.43:1, 보조 글자 4.93:1 / 4.26:1, 성장 4.51:1 / 3.89:1, 위험 3.79:1 / 3.27:1, 주의 5.92:1 / 5.11:1. 일반 외곽선 stone과 일반 면의 대비는 1.97:1, 기본 그리드선 slate는 1.43:1이다. 원본의 낮은 대비와 명도 관계를 보존하는 선택으로, 모든 작은 텍스트·경계가 4.5:1 또는 3:1 목표를 충족하는 것은 아니다. 일반 면 위 위험 텍스트와 제목 면의 보조 글자는 추후 가독성 개선 검토 대상이며 다른 역할을 임의로 변경하지 않는다.

UI의 16색 정의 및 별칭, 기존 스프라이트의 원본 인덱스 및 알파 보존, 실제 표시 데이터의 16색 범위와 설치된 텍스처 일치, 실제 출력 배율별 간격과 조작을 검증한다. 투명도 합성·안티앨리어싱으로 만들어지는 화면 픽셀과 보관용 원본 데이터는 설계 색의 수에 포함하지 않는다. 실제 표시용 RGB 원본은 공통 16색을 사용한다. 신규 첨부 객체의 추가 자체는 범위 밖이다. 실제 사용자 가독성 평가와 타 브라우저/OS는 별도 검증한다.
