# Garden 16 — 게임 공통 색상 가이드

> 적용 기준: 2026-11-13, devel. UI와 게임 오브젝트가 공유하는 단일 디자인 팔레트. 이전 Garden 32 및 UI 전용 16색 안은 역사적 설계로 보존되며 현행 구현 기준이 아니다.
> 색상 원본: [src/palette.js](../src/palette.js). 화면별 크기·좌표는 [현행 UI 규격](./resolution-960x540.md), 간격은 [UI 간격 가이드](./ui-spacing-guide.md)를 따른다.

## 1. 설계 목적

참고 UI의 색상 코드 자체를 복사하지 않는다. 낮은 채도의 중성 면, 명도 단계, 채도 차이와 기능 강조의 관계를 참고한다. 꽃·곤충·동물·도구가 자연스럽게 표현되도록 UI와 에셋에 공통으로 쓸 수 있는 색을 선정한다. 첨부 참고 UI 7장과 향후 객체 시트 2장의 색상 계열을 고려했으며, 참고 이미지 자체를 게임에 반입하지 않는다.

## 3. UI 색상 위계

- 전체 배경은 ink, 상하 HUD와 일반 패널·버튼·슬롯·정원·도안·정보창 면은 panel, 제목 띠와 선택/호버 면은 slate. HUD와 슬롯 면이 같아도 외곽선을 통해 구분한다. 서로 다른 면의 위계는 색뿐 아니라 테두리·여백으로 전달한다.
- 일반 조작 요소와 패널 외곽은 stone, 낮은 중요도의 그리드/보조선은 slate, 선택·포커스 테두리는 sky. 비활성 버튼은 ink 면과 slate 경계, 잠긴 슬롯은 기존 프레임 규격을 유지한다. HUD 두 경계선은 panel/slate, 내부 구분과 빈 게이지는 ink.
- 주요 글자·수치·제목은 paper, 레이블·설명은 silver, 비활성·비용·보조 안내는 stone. 동일 의미는 같은 역할을 사용한다.
- 긍정/성장/배치 가능은 growth, 부정/위험은 red, 주의/중요 안내는 gold, 자원은 sky. 보라색은 객체나 의미 있는 특수 강조에 사용하며 필요 없이 UI를 장식하지 않는다. 경고색은 현행 UI에서 예약 역할로 유지한다.
- 기능적 색상은 글자·아이콘·상태 등 필요한 위치에만 사용한다. 일반 제목은 밝은 중성색을 유지하고 성공/실패는 패널 외곽으로 의미색을 표시한다. 위험 버튼은 호버 상태에서도 짙은 면을 유지해 빨간 글자의 대비를 보존하고 포커스 테두리로 호버를 전달한다. 색만으로 상태를 전달하지 않는다.

## 4. 신규 객체의 색상 선택 원칙

1. **소재와 일반적인 인식부터 결정:** 종이·흰 토끼·흰 꽃잎은 밝은 중성 계열, 돌과 금속은 회색, 흙과 목재는 자연 갈색, 잎과 곤충은 녹색처럼 첫인상에 맞는 색을 먼저 선택한다. 모든 객체를 참조 이미지와 같은 색으로 만들 필요는 없다.
2. **기본색 → 명암 → 특징색:** 객체의 대표색 하나를 정하고 필요할 때만 그림자 또는 하이라이트를 추가한다. 16px 등 작은 아이콘에서는 실루엣과 핵심 특징을 먼저 읽을 수 있어야 하므로 보통 2~4개 색부터 시작한다. 더 많은 색이 실제로 도움이 되는지 목표 크기에서 확인한다.
3. **근접 소재끼리 공유:** 한 색이 UI 경계와 금속, 글자와 흰 종이, 성장 표시와 밝은 잎 등 여러 역할을 맡을 수 있다. 같은 소재나 의미에 비슷한 새 HEX를 임의 추가하지 않는다.
4. **명암이 부족하면 기존 색을 활용:** 명도 차이를 확보하기 위해 다른 중성색이나 자연 소재색을 사용한다. 예를 들어 어두운 까마귀·도구는 중간톤/밝은 부분으로 실루엣을 보강한다. 모든 객체에 일률적인 외곽선을 강제하지 않는다.
5. **원본과 표시를 구분:** 원본 이미지와 픽셀 인덱스, 형태, 해상도, 투명도는 보존한다. 기존 샘플의 표시색은 `test-sprites.js`에서 소재 역할을 선택한다. 새 에셋도 원본 보존 후 게임에 사용할 픽셀 색을 Garden 16으로 제작·검증한다. 원본 자체를 강제 덮어쓰거나 단순 최근접 양자화만으로 표현력을 결정하지 않는다.
6. **예외는 승인 후:** 16색만으로 기능 구분 또는 객체 표현이 어렵다면 기존 색을 재사용하거나 명암·형태를 개선하는 방안을 우선 확인한다. 새 색 필요성, 기존 팔레트에 미치는 영향 및 실제 크기 비교를 기록하고 승인 후 변경한다.

## 5. 대비와 검증

sRGB 상대 휘도로 계산한 명암비이다. 실제 픽셀 글꼴·저해상도 가독성과 동일한 평가가 아니다.

| 전경 역할 | panel 배경 | slate 배경 |
| --- | ---: | ---: |
| paper | 11.35:1 | 6.79:1 |
| silver | 8.06:1 | 4.83:1 |
| stone | 4.56:1 | 2.73:1 |
| growth | 6.67:1 | 3.99:1 |
| red | 4.61:1 | 2.76:1 |
| gold | 7.69:1 | 4.60:1 |
| sky | 5.53:1 | 3.31:1 |

일반 작은 텍스트는 4.5:1 이상, 기능적 외곽선은 3:1 이상을 목표로 한다. 비활성 글자와 기능색은 짙은 배경에 배치하고 낮은 대비의 장식 선을 정보 전달에 단독 사용하지 않는다. 어두운 실루엣과 낮은 대비의 객체는 실제 출력에서 별도 확인한다. 위 수치는 모든 화면이 접근성 기준을 충족한다는 보증이 아니다.

- 새 UI와 에셋은 `GardenPalette`의 역할 또는 소재 토큰으로 정의하고 임의 HEX를 선언하지 않는다. 시작 화면의 CSS fallback 및 렌더러의 비가시 마스크 색은 예외다.
- UI 색·현재 스프라이트의 알파가 있는 원본 RGB·월드 임시 도형의 색을 공통 원본 값으로 검사한다. 투명 픽셀, 알파 합성, 안티앨리어싱으로 발생하는 화면 픽셀 색은 16색 제한 대상이 아니다.
- 실제 목표 스프라이트 크기, 960×540 및 배율별 실제 렌더링, 역할 간 구분과 조작을 검증한다. UI 배율·간격의 상세 검증은 [ui-scale-audit.md](./ui-scale-audit.md).
- 첨부된 모든 신규 객체는 아직 게임에 추가되지 않았다. 현재 적용은 기존 UI와 테스트 꽃·달팽이·손수레, 수호자·보석 임시 도형 및 개발용 카드 비교 페이지 범위이다. 이후 추가되는 객체에도 이 가이드를 사용한다.
