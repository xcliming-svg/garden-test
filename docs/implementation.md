- 기준: `main`의 전장 UI 병합 커밋 [74caa36](https://github.com/xcliming-svg/garden-test/commit/74caa3657ff11565a4080fedcfd71faadf85c86f)

## 1. 게임 구성 시스템

### 확정 설계

정원 도안을 받아 정원을 확장하고, 정원을 지키는 수호자 주변으로 몰려오는 적을 처치하는 로그라이크 게임을 목표로 한다. 대규모 적과 드롭 아이템, 정원을 동시에 인식할 수 있는 전장 구성을 적용한다.

| 요소 | 확정한 역할 |
| --- | --- |
| 정원 | 도안에 맞추어 확장하는 최대 10×10칸의 공간 |
| 수호자 | 정원 주위를 계속 돌며 정원을 지키는 캐릭터 |
| 적 | 정원 주변으로 몰려오는 다수의 적 |
| 보석 | 전장 드롭 재화 및 장착 슬롯 확장에 사용하는 재화 |
| 회복약 | 전장에 떨어지는 하트 형태의 회복 아이템 |
| 네모 아이템 | 전장에서 하단 장착 슬롯으로 드래그할 아이템 |
| 도안 | 완성할 정원의 형태를 보여주는 최대 10×10칸의 축소 UI |

### 적용 구현

이 구성을 표현하는 정적 전장 UI를 적용했다. 수호자, 적, 보석, 회복약, 네모 아이템은 크기 비교를 위한 정사각형 임시 도형으로 고정 배치한다. 실제 그림, 이동, 상호작용, 게임 상태는 아직 없다.

정원 확장, 수호자 순환 이동, 적 스폰, 공격, 충돌, 대규모 처치, 아이템 드롭·획득·장착은 확정된 게임 방향을 설명하는 내용이며 구현 완료가 아니다. 공격 방식, 성장 수치, 적의 행동, 도안 데이터, 확장 비용 등의 상세 규칙은 미정이다.

## 2. 실행 및 렌더링 시스템

| 항목 | 적용 내용 |
| --- | --- |
| 엔진 | Phaser 3.90.0 고정 버전 |
| 실행 | 빌드 도구 없이 `index.html`을 브라우저로 열어 실행. CDN 접근 필요 |
| 화면 비율 | 16:9 |
| 전장 논리 좌표 | 640×360 |
| 실제 캔버스 | 브라우저에서 들어가는 최대 16:9 크기. 16×9 단위로 계산 |
| 배율 | 비정수 배율 허용. 창 크기에 따라 카메라 배율 재계산 |
| 메뉴 좌표 | 기존 1280×720 디자인 좌표를 실제 캔버스에 매핑 |
| 텍스트 | Departure Mono / Galmuri11 Condensed·Bold; 실제 카메라 배율(최소 1)로 텍스처 해상도 조정 |
| 픽셀아트 | 실제 에셋 추가 시 이미지별 최근접 이웃 필터 적용 예정 |

640×360은 전장 좌표와 에셋의 1배 크기를 정의하는 기준이다. 전체 캔버스를 640×360으로 고정해서 확대하는 방식은 사용하지 않는다. 720p·1080p·1440p·4K의 전체 16:9 영역에서는 각각 논리 좌표 대비 2·3·4·6배가 된다. 창의 가용 CSS 픽셀이나 브라우저 배율에 따라 실제 값은 달라질 수 있다.

**코드:** [index.html](../index.html), [src/main.js](../src/main.js)의 `fitParent`, [src/ui.js](../src/ui.js)의 `fitCamera`, `text`, `loadFonts`.

### UI 글꼴

영문·숫자는 Departure Mono 1.500, 한글 일반 텍스트는 Galmuri11 Condensed 2.40.3, 강조 텍스트는 Galmuri11 Bold 2.40.3을 선택한다. 실제 WOFF2 바이트는 로컬 CSS에 데이터 URL로 내장하며 저작권 및 OFL 전문을 `assets/fonts/`에 보존한다. 영문 11px 배수, 한글 12px 배수를 기본 논리 크기로 적용한다. 슬롯 비용은 기존 24px 가로 배치와 세 자리 요구량 유지를 위해 7/6px 예외를 유지한다. 영문 굵은꼴 합성은 하지 않는다. [폰트 원본 및 라이선스](../assets/fonts/README.md). 폰트 로드 실패 시 시스템 글꼴로 대체하고 경고한다. 실제 브라우저 렌더링 검증은 별도 확인이 필요하다.

**미구현:** 오프라인 실행 패키지, Steam SDK 및 배포 패키징, 실제 이미지 필터 연결, 그래픽 설정 변경·저장.

## 3. 씬 및 메뉴 시스템

Phaser Scene으로 화면을 분리하고, 메뉴에서 하위 화면을 열 때 부모 씬을 일시정지한 후 오버레이 씬을 실행하는 구조를 적용했다. 실제 게임의 진행 상태에 따른 자동 씬 전환은 없다.

| 씬 | 적용 구현 |
| --- | --- |
| Boot | 로컬 폰트 로드 후 Phaser 시작, Boot에서 MainMenu로 이동 |
| MainMenu | 새 게임, 이어하기(비활성), 설정, 도감, 종료(웹 비활성). 안내 패널·크레딧 메뉴 없음 |
| Game | 상단 HUD, 중앙 정원과 전장, 접이식 도안, 하단 장착 슬롯 |
| Pause | ESC로 Game 일시정지, 계속하기/ESC로 복귀, 재시작(비활성), 설정·도감·메인 메뉴 |
| Settings | 일반·사운드·화면 탭 전환 및 돌아가기 |
| Codex | 맵 도감의 자리 확보. 기존 조작법 씬을 대체 |
| Confirm | 메인 메뉴 복귀 확인. 취소 시 Pause 복귀, 확인 시 Game·Pause 종료 |
| Victory | 성공 결과 UI 및 새 게임·메인 메뉴 버튼 |
| Defeat | 실패 결과 UI 및 새 게임·메인 메뉴 버튼 |

성공/실패 화면은 `index.html?preview=1`의 메인 메뉴에서 개발용 버튼으로만 확인할 수 있다. 결과 통계는 대시로 표시하며 승패 판정이나 결과 데이터와 연결되지 않는다. 이어하기, 재시작, 웹 종료 버튼은 실제 기능이 없어 비활성이다. 설정과 도감의 콘텐츠 및 저장 로직은 미구현이다.

메뉴 버튼은 기존 1280×720 좌표 기준 높이 48px, 주요 버튼 사이 간격 8px을 적용한다. 설정 행의 레이블과 값은 같은 세로 중심선을 사용한다. 공통 버튼, 패널, 텍스트, ESC 처리, 오버레이 유틸리티는 `GardenUI`에 분리했다.

**코드:** [src/scenes.js](../src/scenes.js), [src/ui.js](../src/ui.js). 상세 전환 계약은 [AGENTS.md](../AGENTS.md)의 씬 전환 계약을 참조한다.

## 4. 전장 및 정원 시스템

정원과 주변 전투 공간의 비율을 고정하기 위해 640×360 논리 좌표를 다음과 같이 구성했다.

| 영역 | 논리 크기 | 논리 좌표(좌상단) |
| --- | --- | --- |
| 상단 HUD | 640×24 | 0, 0 |
| 전장 | 640×300 | 0, 24 |
| 하단 HUD | 640×36 | 0, 324 |
| 최대 정원 | 160×160 | 240, 94 |
| 정원 한 칸 | 16×16 | — |

정원을 전장 중앙에 10×10 빈 그리드로 표시한다. 정원 외부 전장에는 그리드를 그리지 않는다. 최대 정원은 전장 면적의 약 13.3%를 차지하고, 정원 좌우에는 각 240px, 상하에는 각 70px의 여유가 있다. 도안 패널이 일부 전장에 중첩된다.

**적용 구현:** 정원 최대 크기 전체를 나타내는 정적 그리드, 어두운 녹색 전장, 수호자 및 드롭/적의 크기 비교 도형.

**미구현:** 실제 정원 타일 배치, 도안에 따른 꽃이나 그림 표현, 정원 성장 상태, 맵 및 전투 시스템. 현재 전장 치수는 전투 밀도나 밸런스를 검증한 결과가 아니다.

**코드:** [src/game-layout.js](../src/game-layout.js)의 `spec.garden`, `grid`, `drawMarkers`, `draw`.

## 5. 상단 HUD 시스템

상단에는 시간 → 처치 수 → 정원 완성도 → 보석 순으로 정보를 배치했다. 모든 레이블은 데이터의 왼쪽에 표시하며 보석은 레이블 없이 아이콘 공간과 숫자만 표시한다. 정원 완성도는 게이지 내부의 현재 퍼센트를 표시하고 끝에 별도의 100% 문구를 넣지 않는다.

| 정보 | 현재 표시 | 배치 규칙 |
| --- | --- | --- |
| 시간 | 시간 00:00 | 레이블 + 시간 표시 폭 |
| 처치 수 | 처치 수 0 | 레이블 + 5자리 수치 예약 폭 |
| 정원 완성도 | 0% | 나머지 가용 폭의 게이지 |
| 보석 | 점선 아이콘 자리 + 0 | 12×12 아이콘 공간 + 5자리 수치 예약 폭 |

컬럼 폭을 임의 고정 좌표로 지정하지 않고 레이블 실측 폭, 수치 예약 폭, 내부 간격 4px, 좌우 패딩 각 8px을 합산해 계산한다. 시간 예약 문자열은 `88:88`, 처치 수·보석은 `88888`이다. 이는 실제 시간이나 재화의 게임상 최대값이 아니다. 컬럼 사이에는 1px 구분선을 넣는다. 모든 요소의 세로 중심선은 y=12, 레이블은 12px, 수치는 11px, 게이지 높이는 12px이다.

**적용 구현:** 초기 수치와 빈 게이지, 콘텐츠 기반 컬럼 배치, 구분선, 보석 이미지 예약 공간. 초기 레이아웃 계산만 구현되어 있고 수치에 대한 실제 데이터 바인딩이나 실시간 갱신은 없다.

**미구현:** 경과 시간 계산, 처치 수 집계, 정원 완성도 판정, 보석 재화 집계 및 실제 보석 이미지.

**코드:** `src/game-layout.js`의 `hud`, `metricValue`, `metricWidth`, `drawHud`.

## 6. 도안 시스템

정원 도안을 전장 좌상단에 축소해서 표시하고 제목 클릭으로 접거나 펼치는 UI를 적용했다. 도안은 전장 영역의 위치나 정원 크기를 변경하지 않는 오버레이이다.

| 항목 | 논리 규격 |
| --- | --- |
| 그리드 | 최대 10×10, 한 칸 8px |
| 전체 도안 | 80×80 |
| 실제 정원 대비 | 50% |
| 펼침 패널 | 88×104 |
| 접힘 패널 | 88×16 |
| 헤더 | 높이 16px |
| 그리드 내부 패딩 | 상하좌우 4px |
| 위치 | x=8, y=32 |

패널 폭과 높이는 그리드, 헤더 및 패딩을 합산해 계산한다. 초기에는 펼친 상태이며 클릭으로 본문 가시성과 화살표 방향을 전환한다. 제목은 접힌 후에도 유지된다.

**미구현:** 실제 도안 이미지, 도안 선택·획득, 정원과 도안의 데이터 동기화 및 완성도 계산.

**코드:** `src/game-layout.js`의 `spec.blueprint`, `drawBlueprint`.

## 7. 장착 슬롯 시스템

### 확정 설계

- 초기 장착 가능 슬롯 4개, 최대 10개.
- 일반 슬롯 옆에 동일한 크기의 확장 슬롯 1개를 표시한다.
- 확장 슬롯은 보석 아이콘과 비용(최대 세 자리)을 유지하고, 보석이 부족하면 흐린 색상, 충족하면 밝은 색상으로 표현한다. 더하기 기호·자물쇠·빈 슬롯 문구는 사용하지 않는다.
- 확장 시 일반 슬롯이 추가되고 다음 확장 슬롯을 표시하며 최대 10개에 도달하면 확장 슬롯을 표시하지 않는다.
- 전장의 네모 아이템은 하단 슬롯에 드래그하여 장착하는 방향으로 설계한다.

### 적용 구현

하단 중앙에 24×24 일반 슬롯 4개와 비활성 확장 슬롯 1개를 배치했다. 슬롯 간격은 4px이며 표시 개수·크기·간격으로 전체 너비와 시작 위치를 계산한다. 일반 슬롯의 테두리는 완성도 게이지와 같은 색상이다.

| 상태 | 테두리 | 내부 | 비용 표시 |
| --- | --- | --- | --- |
| 일반 빈 슬롯 | #687B6D | #101719 | 없음 |
| 확장 불가능 | #39453F | #191F22 | #87958D |
| 확장 가능(설계 색상) | #9AB59E | #26382D | #B7D0BA |

확장 슬롯의 6×6 아이콘 예약 공간과 숫자를 한 행으로 중앙 정렬한다. 아이콘과 숫자 사이 2px, 좌우 최소 패딩 2px, 가장 넓은 세 자리 숫자를 기준으로 공통 폰트 크기 7px(필요 시 6px)을 선정한다. 현재는 최대 세 자리 표시 확인을 위해 **999**를 출력하며, 이 값은 실제 비용이 아니다.

**미구현:** 보석 충족 판정, 활성 색상 전환, 확장 클릭 및 보석 소비, 슬롯 추가 및 최대 개수 처리, 아이템 드래그·장착·해제. `max=10`과 활성 색상은 규격 정의에만 존재한다. 실제 비용은 미정이다.

**코드:** `src/game-layout.js`의 `spec.slots`, `slotCost`, `drawSlots`, `drawSlotCost`.

## 8. 에셋 및 시각 규격 시스템

SNKRX처럼 단순하고 러프한 픽셀아트 방향을 적용하기로 했다. 이미 제작된 정사각형 SVG 원본은 보존하고, 향후 목표 크기의 PNG로 래스터화한다. 실제 PNG 파일은 현재 저장소에 들어 있지 않다.

| 요소 | PNG 목표 크기 | 720p 표시 | 임시 표현 |
| --- | --- | --- | --- |
| 정원 타일 | 16×16 | 32×32 | 그리드 |
| 수호자 | 16×16 | 32×32 | 청록색 사각형 |
| 일반 적 | 12×12 | 24×24 | 붉은색 사각형 |
| 보석 | 8×8 | 16×16 | 파란색 사각형 |
| 회복약 | 10×10 | 20×20 | 분홍색 사각형 |
| 네모 아이템 | 16×16 | 32×32 | 황색 사각형 |

에셋별 크기와 제안 경로, 텍스처 키를 `GardenGameLayout.assets`에 정의했다. `drawMarkers`의 도형은 실제 목표 PNG와 같은 크기이며 중심 좌표를 기준으로 배치한다. 향후 이미지 교체 시 같은 중심점과 규격을 사용할 수 있다. 현재 색상과 고정 배치 위치·수량은 크기 검토용으로 최종 아트나 스폰 규칙이 아니다.

**미구현:** 에셋 파일, PNG 변환, preload, 애니메이션, 텍스처별 필터 설정, 실제 충돌 영역.

**상세 규격:** [ASSET_SPECS.md](../ASSET_SPECS.md). 간격 체계, 정확한 좌표, 색상, 에셋 제안 경로, 디자인 참고 자료는 이 문서를 기술 기준으로 사용한다.

## 9. 검증 상태 및 현재 한계

- 기존 화면 작업은 사용자 요청에 따라 실행·자동·빌드 테스트를 하지 않았다. 이 문서는 소스와 확정 설계를 대조한 정리다.
- UI 렌더링 코드가 있다는 사실과 실제 브라우저에서 화면이 정상 동작한다는 검증 결과는 구분한다.
- 저장소는 현재 플레이 가능한 로그라이크 게임이나 Steam 실행 패키지가 아니라 정적 화면 프로토타입이다.
- 저장소 `main`에는 전장 UI 변경이 병합되어 있다. 현재 로컬 작업 폴더는 Git 메타데이터가 없는 파일 사본이며, GitHub와 파일 내용 일치 여부를 별도로 확인한다.
