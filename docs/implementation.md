- 기준: `feature/item-card-ui`의 UI 테스트 시안. 이전 기준은 `main`의 전장 UI 병합 커밋 [74caa36](https://github.com/xcliming-svg/garden-test/commit/74caa3657ff11565a4080fedcfd71faadf85c86f)
- 최초 정리: 2026-11-12
- 개발 단계: 화면 구조 및 전장 크기 검토용 프로토타입
- 판정 기준: 사용자와 확정한 내용 및 실제 저장소 소스. 실행 테스트 완료를 의미하지 않는다.

## 1. 게임 구성 시스템

### 확정 설계

정원 도안을 받아 정원을 확장하고, 정원을 지키는 수호자 주변으로 몰려오는 적을 처치하는 로그라이크 게임을 목표로 한다. 대규모 적과 드롭 아이템, 정원을 동시에 인식할 수 있는 전장 구성을 적용한다.

| 요소 | 확정한 역할 |
| --- | --- |
| 정원 | 도안에 맞추어 확장하는 최대 10×10칸의 공간 |
| 수호자 | 정원 주위를 계속 돌며 정원을 지키는 캐릭터 |
| 적 | 정원 주변으로 몰려오는 다수의 적 |
| 보석 | 전장 드롭 재화 및 장착 슬롯 확장에 사용하는 재화 |
| 회복약 | 전장에 떨어지는 하트 형태의 회복 아이템 |
| 네모 아이템 | 전장에서 하단 장착 슬롯으로 드래그할 아이템 |
| 도안 | 완성할 정원의 형태를 보여주는 최대 10×10칸의 축소 UI |

### 적용 구현

이 구성을 표현하는 정적 전장 UI를 적용했다. 수호자, 적, 보석, 회복약, 네모 아이템은 크기 비교를 위한 정사각형 임시 도형으로 고정 배치한다. 실제 그림, 이동, 게임 상태는 아직 없다. 노란 카드만 정보창 및 테스트용 드래그·장착/교체 UI 상호작용을 제공한다.

정원 확장, 수호자 순환 이동, 적 스폰, 공격, 충돌, 대규모 처치, 아이템 드롭·획득·장착은 확정된 게임 방향을 설명하는 내용이며 구현 완료가 아니다. 공격 방식, 성장 수치, 적의 행동, 도안 데이터, 확장 비용 등의 상세 규칙은 미정이다.

## 2. 실행 및 렌더링 시스템

| 항목 | 적용 내용 |
| --- | --- |
| 엔진 | Phaser 3.90.0 고정 버전 |
| 실행 | 빌드 도구 없이 `index.html`을 브라우저로 열어 실행. CDN 접근 필요 |
| 화면 비율 | 16:9 |
| 전장 논리 좌표 | 640×360 |
| 실제 캔버스 | 브라우저에서 들어가는 최대 16:9 크기. 16×9 단위로 계산 |
| 배율 | 비정수 배율 허용. 창 크기에 따라 카메라 배율 재계산 |
| 메뉴 좌표 | 기존 1280×720 디자인 좌표를 실제 캔버스에 매핑 |
| 텍스트 | Fusion Pixel 10px Proportional KO Regular 단일 폰트; 실제 카메라 배율(최소 1) 해상도, NEAREST(sharp 확정), 글리프 픽셀 원본 보존 |
| 픽셀아트 | 실제 에셋 추가 시 이미지별 최근접 이웃 필터 적용 예정 |

640×360은 전장 좌표와 에셋의 1배 크기를 정의하는 기준이다. 전체 캔버스를 640×360으로 고정해서 확대하는 방식은 사용하지 않는다. 720p·1080p·1440p·4K의 전체 16:9 영역에서는 각각 논리 좌표 대비 2·3·4·6배가 된다. 창의 가용 CSS 픽셀이나 브라우저 배율에 따라 실제 값은 달라질 수 있다.

**코드:** [index.html](../index.html), [src/main.js](../src/main.js)의 `fitParent`, [src/ui.js](../src/ui.js)의 `fitCamera`, `text`, `loadFonts`.

### UI 글꼴

영문·한글·숫자 모두 사용자가 비교 후 선택한 Fusion Pixel 계열의 10px Proportional KO Regular(400)를 사용한다. 원본 WOFF2 바이트(420,964bytes, Git blob 137d5894d6fdf3570407f6f45a0ec1aaa87ed5d9)는 로컬 CSS에 데이터 URL로 내장하며 저작권 및 OFL 전문을 `assets/fonts/`에 보존한다. 출처 미러의 정확한 upstream 릴리스 버전은 미확인이다. 일반 글자 10px, 강조 제목 20/30px의 논리 크기를 사용하고 메뉴 1280×720 좌표에서는 2배 크기를 적용한다. 합성 Bold, 임의 자폭/자간 조절은 하지 않는다. 슬롯 비용은 기존 가로 24px 세 자리 배치를 위해 7/6px 예외를 유지한다. 하단 능력치 레이블·수치·증감 및 아이템 정보창에는 7px 예외를 적용한다. 폰트 로드 실패 시 조용히 대체 폰트로 시작하지 않고 오류를 표시한다. [폰트 원본 및 라이선스](../assets/fonts/README.md). 원본 폰트 비교 페이지에서 사용자가 Fusion Pixel을 선정했으며 이후 크기 축소 요청에 따라 10px 네이티브 규격으로 조정했다. 텍스트 해상도 1 고정 방식은 사용자 확인에서 블러가 심해져 폐기했다. 실제 카메라 배율(최소 1)의 래스터화를 유지하며 창 크기 변경 시 텍스처 해상도를 동기화한다. 사용자 비교에서 sharp와 crisp의 시각 차이가 미미하여 고해상도 NEAREST(sharp)를 단일 렌더링 방식으로 확정한다. 알파 직접 보정과 비교 URL 분기는 제거했다. 창 크기와 텍스트 갱신 시 필터를 유지한다. 실제 브라우저 시각 검증은 별도로 필요하다. 6~7px 슬롯 비용은 네이티브 10px 미만의 예외이며 비정수 배율에서 픽셀 폭이 불균일할 수 있다.

**미구현:** 오프라인 실행 패키지, Steam SDK 및 배포 패키징, 실제 이미지 필터 연결, 그래픽 설정 변경·저장.

## 3. 씬 및 메뉴 시스템

Phaser Scene으로 화면을 분리하고, 메뉴에서 하위 화면을 열 때 부모 씬을 일시정지한 후 오버레이 씬을 실행하는 구조를 적용했다. 실제 게임의 진행 상태에 따른 자동 씬 전환은 없다.

| 씬 | 적용 구현 |
| --- | --- |
| Boot | 로컬 폰트 로드 후 Phaser 시작, Boot에서 MainMenu로 이동 |
| MainMenu | 새 게임, 이어하기(비활성), 설정, 도감, 종료(웹 비활성). 안내 패널·크레딧 메뉴 없음 |
| Game | 상단 HUD, 중앙 정원과 전장, 접이식 도안, 하단 장착 슬롯 |
| Pause | ESC로 Game 일시정지, 계속하기/ESC로 복귀, 재시작(비활성), 설정·도감·메인 메뉴 |
| Settings | 일반·사운드·화면 탭 전환 및 돌아가기 |
| Codex | 맵 도감의 자리 확보. 기존 조작법 씬을 대체 |
| Confirm | 메인 메뉴 복귀 확인. 취소 시 Pause 복귀, 확인 시 Game·Pause 종료 |
| Victory | 성공 결과 UI 및 새 게임·메인 메뉴 버튼 |
| Defeat | 실패 결과 UI 및 새 게임·메인 메뉴 버튼 |

성공/실패 화면은 `index.html?preview=1`의 메인 메뉴에서 개발용 버튼으로만 확인할 수 있다. 결과 통계는 대시로 표시하며 승패 판정이나 결과 데이터와 연결되지 않는다. 이어하기, 재시작, 웹 종료 버튼은 실제 기능이 없어 비활성이다. 설정과 도감의 콘텐츠 및 저장 로직은 미구현이다.

메뉴 버튼은 기존 1280×720 좌표 기준 높이 48px, 주요 버튼 사이 간격 8px을 적용한다. 설정 행의 레이블과 값은 같은 세로 중심선을 사용한다. 공통 버튼, 패널, 텍스트, ESC 처리, 오버레이 유틸리티는 `GardenUI`에 분리했다.

**코드:** [src/scenes.js](../src/scenes.js), [src/ui.js](../src/ui.js). 상세 전환 계약은 [AGENTS.md](../AGENTS.md)의 씬 전환 계약을 참조한다.

## 4. 전장 및 정원 시스템

정원과 주변 전투 공간의 비율을 고정하기 위해 640×360 논리 좌표를 다음과 같이 구성했다.

| 영역 | 논리 크기 | 논리 좌표(좌상단) |
| --- | --- | --- |
| 상단 HUD | 640×24 | 0, 0 |
| 전장 | 640×300 | 0, 24 |
| 하단 HUD | 640×36 | 0, 324 |
| 최대 정원 | 160×160 | 240, 94 |
| 정원 한 칸 | 16×16 | — |

정원을 전장 중앙에 10×10 빈 그리드로 표시한다. 정원 외부 전장에는 그리드를 그리지 않는다. 최대 정원은 전장 면적의 약 13.3%를 차지하고, 정원 좌우에는 각 240px, 상하에는 각 70px의 여유가 있다. 도안 패널이 일부 전장에 중첩된다.

**적용 구현:** 정원 최대 크기 전체를 나타내는 정적 그리드, 공통 웜 블랙(#191B19) 전장, 수호자 및 드롭/적의 크기 비교 도형.

**미구현:** 실제 정원 타일 배치, 도안에 따른 꽃이나 그림 표현, 정원 성장 상태, 맵 및 전투 시스템. 현재 전장 치수는 전투 밀도나 밸런스를 검증한 결과가 아니다.

**코드:** [src/game-layout.js](../src/game-layout.js)의 `spec.garden`, `grid`, `drawMarkers`, `draw`.

## 5. 상단 HUD 시스템

사용자가 확정한 짧은 한 줄 HUD를 적용한다. 상단 24px, 하단 36px, 시간 → 처치 수 → 보석 → 정원 완성도 순. 정원은 전장 중심에 배치한다.

| 정보 | 기본 표시 | 표시 폭 예약 |
| --- | --- | --- |
| 시간 | 00:00:00 | 시 4자리 + 분·초 각 2자리, 콜론 2개 |
| 처치 수 | 0 | 쉼표를 포함한 12자리 정수 |
| 보석 | 점선 아이콘 + 0 | 처치 수와 동일한 12자리 |
| 정원 완성도 | 30% | 마지막 남은 열 폭의 게이지(높이 12px, 최소 폭 64px) |

실제 Fusion Pixel 10px 폰트의 가장 넓은 숫자 글리프를 기준으로 예약 폭을 계산한다. 시간·처치 수·보석의 열 폭은 모두 동일하며 최소 144px이다. 레이블 또는 12px 아이콘, 4px 간격, 좌우 각 8px 패딩을 포함한 세 항목 중 가장 넓은 요구 폭을 8px 단위로 올림해 공유한다. 각 레이블·아이콘은 왼쪽 패딩부터 시작하며 숫자는 바로 뒤 4px 간격에 왼쪽 정렬한다. 값이 증가해도 예약 폭 내에서는 기준점과 구분선이 바뀌지 않는다. 모든 항목의 세로 중심 y=12. 완성도는 마지막 열의 남은 가용 폭에 배치하며, 게이지 테두리 #777D6D, 배경 #101210, 채움 #B3D96A, 퍼센트는 내부 중앙 정렬이며 밝은 채움과 겹칠 때 대비를 보정한다. 상·하단의 배경은 전장과 동일하고 외곽 프레임을 제거했으며, 수평 경계선과 1×16px 세로 구분선(#45483D)만 유지한다.

시간은 시 자리를 최소 두 자리로 표시하고 더 큰 시간은 잘라내지 않는다. 수치는 쉼표로 구분하며 정밀도 보존을 위해 문자열로 포맷한다. 시 4자리 및 수치 12자리 예약은 게임상의 상한을 의미하지 않는다. 실제 값이 예약을 초과하면 그 실측 폭을 반영할 수 있으나 최소 게이지 폭 확보가 불가능한 경우 현재 배치 함수는 오류를 발생시키므로 극단적으로 큰 값의 축약/상세 표시 정책은 추후 수치 규칙 확정 시 결정한다.

**적용 구현:** 한 줄 HUD, 실제 폭 측정 및 시간·처치 수·보석 동일 열 폭, 인접 숫자 배치, 시간·수치 표시 형식, 30% 정적 게이지, 구분선, 보석 이미지 예약 공간. `index.html?hud=stress`의 새 게임에서 9999:59:59 및 양쪽 999,999,999,999를 표시하여 레이아웃을 비교한다. 두 모드는 같은 예약 폭을 사용한다.

**미구현:** 경과 시간 계산, 처치 수 집계, 정원 완성도 판정, 보석 재화 집계 및 실제 보석 이미지. 모든 예시값은 정적이다.

**코드:** `src/game-layout.js`의 `hud`, `formatHudTime`, `formatHudCount`, `hudColumns`, `drawHud`.

## 6. 도안 시스템

정원 도안을 전장 좌상단에 축소해서 표시하고 제목 클릭으로 접거나 펼치는 UI를 적용했다. 도안은 전장 영역의 위치나 정원 크기를 변경하지 않는 오버레이이다.

| 항목 | 논리 규격 |
| --- | --- |
| 그리드 | 최대 10×10, 한 칸 8px |
| 전체 도안 | 80×80 |
| 실제 정원 대비 | 50% |
| 펼침 패널 | 88×104 |
| 접힘 패널 | 88×16 |
| 헤더 | 높이 16px |
| 그리드 내부 패딩 | 상하좌우 4px |
| 위치 | x=8, y=32 |

패널 폭과 높이는 그리드, 헤더 및 패딩을 합산해 계산한다. 초기에는 펼친 상태이며 클릭으로 본문 가시성과 화살표 방향을 전환한다. 제목은 접힌 후에도 유지된다.

**미구현:** 실제 도안 이미지, 도안 선택·획득, 정원과 도안의 데이터 동기화 및 완성도 계산.

**코드:** `src/game-layout.js`의 `spec.blueprint`, `drawBlueprint`.

## 7. 장착 슬롯 시스템

### 확정 설계

- 초기 장착 가능 슬롯 4개, 최대 10개.
- 일반 슬롯 옆에 동일한 크기의 확장 슬롯 1개를 표시한다.
- 확장 슬롯은 보석 아이콘과 비용(최대 세 자리)을 유지하고, 보석이 부족하면 흐린 색상, 충족하면 밝은 색상으로 표현한다. 더하기 기호·자물쇠·빈 슬롯 문구는 사용하지 않는다.
- 확장 시 일반 슬롯이 추가되고 다음 확장 슬롯을 표시하며 최대 10개에 도달하면 확장 슬롯을 표시하지 않는다.
- 전장의 네모 아이템은 하단 슬롯에 드래그하여 장착하는 방향으로 설계한다.

### 적용 구현

하단 중앙에 UI 최대 폭 테스트용 24×24 일반 슬롯 9개와 비활성 확장 슬롯 1개를 배치했다. 실제 초기 4칸·최대 일반 10칸 설계는 변경하지 않는다. 슬롯 간격은 4px이며 표시 개수·크기·간격으로 전체 너비와 시작 위치를 계산한다. 일반 슬롯의 네 모서리만 8px 길이의 1px L자 형태로 표시하며 완성도 게이지 테두리와 같은 색상이다. 도안 외부 패널 프레임도 제거한다.

| 상태 | 테두리 | 내부 | 비용 표시 |
| --- | --- | --- | --- |
| 일반 빈 슬롯 | #777D6D | #191B19 | 없음 |
| 확장 불가능 | #45483D | #191B19 | #A2A69A |
| 확장 가능(설계 색상) | #B3D96A | #191B19 | #B3D96A |

확장 슬롯의 6×6 아이콘 예약 공간과 숫자를 한 행으로 중앙 정렬한다. 아이콘과 숫자 사이 2px, 좌우 최소 패딩 2px, 가장 넓은 세 자리 숫자를 기준으로 공통 폰트 크기 7px(필요 시 6px)을 선정한다. 현재는 최대 세 자리 표시 확인을 위해 **999**를 출력하며, 이 값은 실제 비용이 아니다.

**미구현:** 보석 충족 판정, 활성 색상 전환, 확장 클릭 및 보석 소비, 실제 슬롯 추가 및 최대 개수 처리, 실제 장착·해제·획득 및 저장. 실제 비용은 미정이다. 현재 9칸은 UI 최대 폭 검토용이다.

**코드:** `src/game-layout.js`의 `spec.slots`, `slotCost`, `drawSlots`, `drawSlotCost`, `bottomLayout`, `drawItemPreview`.

### 능력치 및 아이템 정보 UI

- 하단 좌측: 방어력, 최대 체력, 행운. 방어력과 최대 체력은 꽃 한 송이 기준, 행운은 도안에 필요한 꽃의 등장 확률에 영향을 주는 설계이다. 실제 확률 공식은 미정이다.
- 하단 우측: 이동 속도, 획득 범위, 초당 피해량. 이동/획득은 사람, 피해량은 장착 무기 기준이며 사람의 체력은 표시하지 않는다. 분류 제목과 꽃 접두어 없이 한글 레이블만 사용한다.
- 배치: 하단 36px, 좌우 각 126px(42px×3열), 바깥 여백 8px, 중앙 276px, 그룹과 슬롯 사이 48px. 레이블·수치·증감 모두 7px. 각 열은 레이블과 수치 행 두 줄을 실측 바운딩 크기 기준 가로·세로 중앙 정렬하고 행 간격 3px, 수치·증감 간격 2px로 유지한다. 증감은 수치 바로 오른쪽에 표시하며 두 텍스트 전체를 중앙 정렬한다. 7px는 10px 원본의 비네이티브 크기로 실제 화면 가독성 확인 필요.
- 노란 카드 및 장착 슬롯에 오버 또는 클릭하면 이름·효과·설명 정보창을 표시한다. 클릭 고정은 다시 클릭 또는 바깥 클릭으로 해제한다. 정보창은 대상 근처에서 위치를 반전/보정하며 상·하단 HUD를 피한다. 하단은 확정하여 변경하지 않는다. 정보창은 7px, 고정 폭 120px, 배경(soil), 구분선(edge), 제목/설명/안내 색상을 유지한다. 테두리는 기존 카드 하이라이트와 같은 Rectangle + setStrokeStyle 방식의 paper(#F1F0E8) 1px 중앙 스트로크를 사용한다. 제목·구분선·설명·효과 수치·상태 안내 순서이며, 교체 제목은 실제 글꼴 폭을 측정해 104px 이하면 한 줄, 초과하면 화살표 앞에서 줄바꿈한다. 개별 이름이 긴 경우 추가 줄바꿈하며, 설명이 길면 104px 가용 폭에서 줄바꿈하고 높이만 조정한다. 모든 색은 Garden 32를 참조한다. 슬롯 선택 및 빈 슬롯 장착·기존 아이템 교체 대상은 골드(#F4B404)로 통일한다. 능력치 증가·감소 색상과 확장 슬롯 규격은 유지한다.
- 카드만 드래그 가능. 일반 슬롯 위에서는 최종 예상 수치와 증감(증가 황록, 감소 빨강)을 표시하며, 장착 슬롯에는 교체되는 이름과 제거/추가 효과를 함께 표시한다. 유효 슬롯에 놓으면 임시 장착/교체, 기존 아이템은 제거. 무효 위치·확장 슬롯·화면 이탈·일시정지에서는 복귀한다. 새 게임에서 초기화한다.
- 임시 기본값은 방어력 12, 최대 체력 100, 행운 0, 이동 속도 100, 획득 범위 48, 초당 피해량 20. 신발/스프링클러/네잎클로버/보호 비료/자석은 UI 샘플이며 값의 단위, 실제 효과, 드롭 확률, 무기 계산은 미확정이다. 실제 게임 계산/전투/확장 로직과 연결하지 않는다.

## 8. 에셋 및 시각 규격 시스템

SNKRX처럼 단순하고 러프한 픽셀아트 방향을 적용하기로 했다. 이미 제작된 정사각형 SVG 원본은 보존하고, 향후 목표 크기의 PNG로 래스터화한다. 실제 PNG 파일은 현재 저장소에 들어 있지 않다.

| 요소 | PNG 목표 크기 | 720p 표시 | 임시 표현 |
| --- | --- | --- | --- |
| 정원 타일 | 16×16 | 32×32 | 그리드 |
| 수호자 | 16×16 | 32×32 | 청록색 사각형 |
| 일반 적 | 12×12 | 24×24 | 붉은색 사각형 |
| 보석 | 8×8 | 16×16 | 파란색 사각형 |
| 회복약 | 10×10 | 20×20 | 분홍색 사각형 |
| 네모 아이템 | 16×16 | 32×32 | 황색 사각형 |

에셋별 크기와 제안 경로, 텍스처 키를 `GardenGameLayout.assets`에 정의했다. `drawMarkers`의 도형은 실제 목표 PNG와 같은 크기이며 중심 좌표를 기준으로 배치한다. 향후 이미지 교체 시 같은 중심점과 규격을 사용할 수 있다. 현재 색상과 고정 배치 위치·수량은 크기 검토용으로 최종 아트나 스폰 규칙이 아니다.

**미구현:** 에셋 파일, PNG 변환, preload, 애니메이션, 텍스처별 필터 설정, 실제 충돌 영역.

**상세 규격:** [ASSET_SPECS.md](../ASSET_SPECS.md). 간격 체계, 정확한 좌표, 색상, 에셋 제안 경로, 디자인 참고 자료는 이 문서를 기술 기준으로 사용한다.

## 9. 검증 상태 및 현재 한계

- 초기 화면 작업은 사용자 요청에 따라 테스트를 하지 않았다. 이후 UI 개선은 JS 구문 및 모의 렌더링/씬/해상도 검증을 수행했다. 이번 카드 UI는 JS 구문과 모의 동작(장착·교체·취소·능력치·정보창 경계·이벤트 해제) 검증을 통과했다. 실제 브라우저 자동 실행 및 빌드 검증은 미실행이다. [UI 확정 기록](./ui-decisions.md)과 [변경 이력](./changes.md)을 참조한다.
- UI 렌더링 코드가 있다는 사실과 실제 브라우저에서 화면이 정상 동작한다는 검증 결과는 구분한다.
- 저장소는 현재 플레이 가능한 로그라이크 게임이나 Steam 실행 패키지가 아니라 정적 화면 프로토타입이다.
- 이전 UI 확정 기록은 `feature/ui-refinement`의 main 병합 대상으로 작성했다. 현재 작업은 별도 `feature/item-card-ui` 브랜치이며 main은 변경하지 않는다. 로컬 작업 폴더는 Git 메타데이터가 없는 파일 사본이며, GitHub와 파일 내용 일치 여부를 별도로 확인한다.

## 10. 확정 디자인 팔레트

Garden 32(`src/palette.js`)를 색상 단일 원본으로 사용한다. 사용자 제공 에셋 참고 이미지의 주요 색 계열을 B안 UI에 맞춰 정규화했으며, 참고 오브젝트는 삽입하지 않았다. 모든 씬의 색상은 팔레트를 참조한다. 상세 32색, 역할 매핑, 보더 규칙 및 대비 수치는 [ASSET_SPECS.md](../ASSET_SPECS.md)를 참조한다. 실제 에셋 변환·추가 및 최종 화면의 브라우저 시각 검증은 수행하지 않았다.
