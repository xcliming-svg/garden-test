# 시스템별 변경 이력

각 구현 변경의 결과를 시스템 단위로 기록한다. 대화 원문 또는 코드 diff의 복제가 아니라 **어떤 시스템에 무엇이 적용되었으며, 무엇이 아직 구현되지 않았는지**를 설명한다. 최신 구현 상태는 [implementation.md](./implementation.md)를 참조한다.

## 이후 기록 규칙

새 변경은 날짜와 작업 제목, 영향을 받은 시스템, 확정 설계 또는 실제 적용 내용, 미구현/제약, 검증 상태를 기록한다. 커밋 메시지 또는 브랜치/PR 참조를 사용해 추적할 수 있게 하되, 같은 커밋의 SHA를 그 커밋 내부에 억지로 기록하지 않는다. 필요한 경우 후속 변경에서 이미 생성된 커밋 링크를 보완한다. 현행 문서에는 최신 상태를 반영하고, 이력은 기존 기록을 유지한다.

## 2026-11-12 — sharp 기본 적용 및 글리프 경계 비교

- 사용자 화면 비교에서 sharp가 약간 개선됨. 고해상도 NEAREST를 기본값으로 채택하고 기존 선형 필터는 `?font=linear`로 유지한다. `?font=sharp`는 동일 기본값이다.
- `?font=crisp` 실험: 실제 해상도에서 그린 글자의 반투명 알파 대비만 2배 강화한다. 원본 글꼴, 크기, 배치, 색상 유지. 10px 미만 및 배경색이 지정된 텍스트는 제외. 변경된 텍스처만 refresh하며 프레임마다 처리하지 않는다.
- 검증: 4개 모드의 모의 픽셀 알파 값, 필터 유지, 8개 배율, 갱신 및 예외 처리, 추적 해제, JS 구문 통과. 실제 브라우저 시각 개선은 확인하지 않았으며 crisp는 기본값이 아니다.

## 2026-11-12 — 글자 렌더링 최종 확정

- 사용자 비교에서 sharp와 crisp의 차이가 미미함. 실제 카메라 배율(최소 1) 래스터화 + 개별 텍스처 NEAREST(sharp)로 단일화한다. 알파 보정 및 linear/crisp URL 분기 제거. 원본 폰트/크기/좌표/팔레트 및 전역 렌더러 설정 유지.
- Text 갱신 후 필터 복원 및 리사이즈 시 style/frame.source 해상도 동기화 유지. Canvas 픽셀 읽기·쓰기나 추가 업로드 없음. 비정수 배율과 기기별 브라우저 래스터화 차이는 남을 수 있다.
- 검증: 전체 5개 JS 구문, 9개 씬 생성, 10개 창 크기(320×180~7680×4320), 텍스트/색상/배경/크기 갱신 시 NEAREST 유지, Canvas 해상도 동기화, 씬 종료 추적 해제, 일반/장시간 HUD 모의 테스트 통과. 실제 브라우저 시각 검증 미실행.

## 2026-11-12 — UI 확정 기록 및 main 병합 준비

- `docs/ui-decisions.md`에 최종 레이아웃, HUD, Garden 32, 보더, 폰트/렌더링 결정과 미정 사항을 정리하고 문서 목차에 연결했다.
- 현재 코드 및 문서 기준을 대조하고 기존 테스트 상태를 최신 모의 검증 결과와 일치시켰다. 구현 코드는 변경하지 않는다. 기존 커밋을 보존하는 병합 방식으로 main에 반영한다.
